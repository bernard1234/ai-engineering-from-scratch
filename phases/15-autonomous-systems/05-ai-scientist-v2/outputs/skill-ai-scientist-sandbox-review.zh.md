给定一个由 AI-Scientist-v2 式循环产出的自主研究成果（假设、代码、实验、图表、论文草稿），产出一份双闸门审查：sandbox 审计（是否有东西外泄？）加上研究审计（工作是否扎实？）。

两道闸门直接对应下列审计：**Sandbox 闸门 = 第 1 项**；**Research 闸门 = 第 2 项（实验审计）+ 第 3 项（打磨审计）**。第 4–5 项规定了两道闸门都通过之后会发生什么。

产出：

1. **Sandbox 闸门。** 在任何产物离开 sandbox 之前：
   - 列出循环发起的每一次网络调用及其目标。标记任何未经预先批准的调用。
   - 清点循环在其工作目录之外写入的每一个文件。
   - 确认 Docker / seccomp / gVisor 的隔离在整次运行中始终有效。
   - 确认没有子进程逃出 sandbox 的监管。
   如果有任何一项检查失败，阻止导出；上报给人类。
2. **实验审计。** 读实验代码，而不是论文：
   - 核实每一项声称的实验确实运行过，且其报告的数字可复现。
   - 检查失败的实验是否被作为失败报告，而不是事后重新包装成负面结果。
   - 检查该想法的“新颖性”标签能否经得起人类领域专家的文献检索。
3. **打磨审计。** 读图表：
   - 确保每一张图表的数据都来自有日志的实验运行，而不是来自打磨阶段的重写。
   - 确认坐标轴、刻度与标注与底层数据一致。
   - 标记任何图注所声称的内容超出数据支持范围的图表。
4. **披露方案。** 如果该产物意图对外分发：
   - 披露该产物由 agent 撰写。
   - 披露所用工具（模型家族、循环版本）。
   - 披露检查过它的真人审查者以及检查了什么。
5. **拒绝发布决策。** 如果产物未通过任何一步审计，默认不发布。要推翻这一默认，必须有一位具名的人类负责人。

硬性拒绝：
- 任何跳过任一道闸门的投稿。
- 任何循环执行日志缺失或不完整的产物。
- 任何无法追溯到某次具体实验运行的图表。
- 任何尚未由领域专家核实的新颖性主张。

拒绝规则：
- 如果运行缺少 Docker 或等价隔离，拒绝，并要求在隔离的 sandbox 中重跑。
- 如果用户无法提供实验阶段的执行日志，拒绝——论文不可审。
- 如果拟议的分发渠道是同行评审的会议或期刊，而用户提议不披露 agent 作者身份，拒绝，并要求披露。

输出格式：

返回一份双闸门报告：
- **Sandbox 闸门结论**（PASS / BLOCK，附理由）
- **Research 闸门结论**（覆盖实验审计（2）与打磨审计（3））（PASS / BLOCK / REQUIRES_EXPERT，附逐项说明）
- **披露方案**（渠道、文本、人类审查者姓名）
- **发布决策**（release / hold / reject）
- **下一步行动**（谁在何时之前做什么）
