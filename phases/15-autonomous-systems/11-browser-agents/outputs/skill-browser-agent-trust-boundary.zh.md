给定一个拟议的浏览器 agent 工作流，产出一份信任边界范围划定文档，逐一枚举每一次读取、每一次写入，以及首次运行所需的最低防御栈。

产出：

1. **读取面。** 列出 agent 将要抓取的每一个 origin。把每个 origin 归类为在信任内（由用户所在组织运营的第一方站点）或信任之外（任何第三方、任何用户生成内容、任何搜索结果）。所有来自信任之外的读取都必须被视为潜在的 prompt injection 通道。
2. **写入面。** 列出 agent 被授权执行的每一个有后果动作（提交表单、发布内容、调用后端工具、写入记忆）。对每一个动作，说明其影响范围和该动作是否可逆。
3. **必需防御。** 最低栈：内容清洗器、读 / 写边界（当 content_origin 来自信任之外时，写入需要重新批准）、按任务配置的工具白名单、带受限凭证的会话隔离、持久记忆上的 canary token、不可逆动作上的 HITL。
4. **benchmark 与分布的匹配度。** 如果 agent 报告了 BrowseComp、OSWorld 或 WebArena-Verified 分数，请说明该 benchmark 与真实任务之间的分布重叠。高 BrowseComp 分数并不能预测订票流程的可靠性。
5. **已知攻击清单。** 确认部署已针对以下攻击做了加固：(a) 可见文本注入，(b) URL 片段 / 查询串注入，(c) 记忆绑定攻击（Tainted Memories 类），(d) 针对已认证会话的 CSRF 式攻击，(e) 一键劫持。对每一项，指明具体防御及其触发位置。

硬性拒绝：
- 浏览器 agent 拥有生产凭证的访问权限且没有会话隔离。
- 任何部署中，由信任之外内容发起的写入不需要重新获得 HITL 批准。
- 任何仅依赖内容清洗器的部署（清洗器只能拦住简单攻击；复杂 payload 会通过）。
- 持久记忆没有 canary 条目。
- 涉及金融交易或客户数据、但写入没有 HITL 的工作流。

拒绝规则：
- 如果用户无法说出一次由注入驱动的错误写入会造成的影响范围，拒绝，并要求给出明确的一句话说明。
- 如果用户提议在不具备受限凭证的栈上部署浏览器 agent，拒绝，并要求先准备独立身份。
- 如果用户以某个 benchmark 分数（BrowseComp、OSWorld、WebArena）作为 agent“能”完成生产任务的证据，拒绝，并要求针对真实分布做内部 eval。

输出格式：

返回一份信任边界备忘录，包含：
- **读取面表格**（origin，在信任内 / 信任之外）
- **写入面表格**（动作、影响范围、是否可逆）
- **防御栈**（已配置各层的项目符号列表）
- **benchmark 匹配度说明**（如适用）
- **已知攻击清单**（五行，每行指明防御）
- **部署结论**（生产 / 预发 / 仅研究）
