# 有界自我改进的设计

> 研究界已经收敛到用四个原语来约束自我改进循环。形式化不变量，必须在每一次编辑前后都成立。不可修改的对齐锚点。多目标约束，要求每个维度（安全、公平、鲁棒性）都成立，而不只是性能。回归检测，在历史指标显示能力损失时暂停循环。它们没有一个是安全性的证明——信息论结果（Kolmogorov complexity、Lob's theorem）限制了一个系统能对自身后继者证明什么。它们是提高静默失败成本的缓解措施。

**Type:** Learn
**Languages:** Python（stdlib，带不变量检查的有界循环）
**Prerequisites:** 第 15 阶段，第 07 课（RSI）、第 15 阶段，第 04 课（DGM）
**Time:** ~60 分钟

## 问题场景

第 07 课的竞赛模拟器显示，微小的速率差异会复利成巨大的差距。第 04 课的 DGM 案例研究表明，循环会主动钻自己 evaluator 的空子。这两个结果都指向同一个工程问题：你能对一个自我改进循环施加哪些约束，使得这些约束无法被循环自身静默地削弱？

ICLR 2026 RSI Workshop 的摘要（openreview.net/pdf?id=OsPQ6zTQXV）指出了四个这样的原语。Anthropic 的 RSP v3.0（第 19 课）与 DeepMind 的 FSF v3（第 20 课）都在能力阈值中引用了它们。Meta HyperAgents 的工作以及 SAHOO（2026 年 3 月）之类的社区框架，在生产中实现了其中的子集。

诚实的框定是：这些都是缓解措施。信息论结果限制了一个系统能对自身后继者证明什么，当前没有任何设计能在形式上闭合这个问题。一个有良好边界的循环比无界的循环更安全，但不是绝对意义上的安全。

## 核心概念

### 原语 1：形式化不变量

不变量是一种必须在每次自我修改前后都成立的属性。例如：

- 输出分布以一段固定的 constitution 头部为条件（第 17 课）。
- 没有任何 tool call 指向未授权的端点。
- 内存写入经过带日志、带签名的路径。
- evaluator 的模块哈希与已批准版本一致。

不变量由循环无法编辑的外部代码来检查。如果某项拟议的修改违反了不变量，它就会被拒绝。这能捕捉 DGM 式的 evaluator 篡改模式（第 04 课）。

难点在于挑选那些对安全而言必要、且能在合理时间内计算的不变量。过度规定会拖慢进展；规定不足则会让循环走过重要属性。

### 原语 2：对齐锚点

对齐锚点是循环核心目标的一种不可变表示，固定在循环可编辑面之外。例如：

- 一份 constitution 文本（第 17 课），在每次调用时从只读位置加载。
- 一个位于独立仓库、拥有独立访问控制的 evaluator。
- 一份由人类签名、每轮重新校验的工具权限清单。

锚点的作用是防止目标漂移。循环可以改进它追求目标的方式，但不能编辑目标本身是什么。

微妙的失效模式：一个循环无法编辑的锚点，仍可能被一个在「如何读取锚点」上发生漂移的循环重新解读。Constitutional AI（第 17 课）明确基于推理，以应对新情境；而解释漂移正是发生在这一推理层。锚点是必要的，但不充分。

### 原语 3：多目标约束

只优化单一标量分数的循环会找到捷径。必须同时满足多个硬约束的循环，可用的捷径就更少。典型的轴：

- 性能（任务级 benchmark）
- 安全（red team 评估、对已知坏例的拒绝率）
- 公平（对敏感子群体的差异化影响上界）
- 鲁棒性（OOD 测试集、对抗性输入处理）

只有当每一个约束都成立时，修改才会被接受。第 13 课的成本治理器把它与财务约束叠加起来。第 18 课的 Llama Guard 作为安全轴接入。

### 原语 4：回归检测

每一轮的分数会与历史分布比较。超出配置容差的下降会暂停循环。这能捕捉原本会被「改进过去」的运行均值吸收掉的能力静默损失。

一个实用的实现：存下最近 N 轮每项任务的分数。每一新轮次计算每项任务的增量。如果任一增量低于阈值，就拒绝该轮，并由人类复核。

### 信息论极限

Kolmogorov complexity 与 Lob's theorem 对系统能对自身证明的东西设定了上界。Schmidhuber 的形式化 Godel Machine（第 04 课）瞄准了这类上界中最高的那个；但没有人完成过非平凡的证明。Lob 的结论是：如果一个系统可证明地相信「如果我能证明我应当做 X，我就会做 X」，它就会在没有证明自己应当做的情况下去做 X——这是一个著名的自指失效。

对我们这些原语的含义是：它们无法闭合安全问题的整体。它们提高了静默失败的成本。一个本会悄悄绕过缺失检查的恶意或漂移的循环，如今必须主动破坏一个显式检查，而这是一种更容易检测的特征。

### 一个具体示例

假设一个 agent 提出一次编辑。门控栈为：

1. 不变量检查：模块哈希、工具权限清单、constitution 头部。
2. 锚点检查：目标陈述与已批准版本一致（逐字节或语义层面）。
3. 多目标评估：性能、安全、公平、鲁棒性各轴。
4. 回归检测：没有任何轴下降超过容差。

四项必须全部通过，编辑才能落地。任何一项失败都会暂停循环。

## Use It

`code/main.py` 在第 04 课 DGM 式玩具演示上运行一个有界自我改进循环，但在其上叠加了四个原语。每个原语都可以单独启用或禁用。演示要说明的是：每个原语都捕捉一类特定的失败，而移除其中任何一个，就会让那一类失败溜过去。

## Ship It

`outputs/skill-bounded-loop-review.md` 审计一个拟议的有界循环，并打分判断它实际实现了四个原语中的哪几个，以及它声称实现了哪几个。

## Exercises

1. 在启用全部原语的情况下运行 `code/main.py`。确认循环在主指标上仍在改进，同时不让那个 hack 得逞。

2. 禁用回归检测。构造一个输入，使由此导致的能力静默损失被接受。

3. 禁用多目标约束。展示循环在性能轴上收敛，而某个安全轴下降。

4. 为一个 coding agent 设计一个对齐锚点。什么文本、存在哪里、如何检查？

5. 阅读 ICLR 2026 RSI Workshop 摘要。从四个原语中挑一个，就当前技术水平提出一个具体的改进。

## Key Terms

| 术语 | 通俗说法 | 实际含义 |
|---|---|---|
| Invariant | 「永远为真的属性」 | 在每次编辑前后由外部代码检查的属性 |
| Alignment anchor | 「固定住的目标」 | 位于循环可编辑面之外的不可变核心目标表示 |
| Multi-objective constraint | 「所有轴都必须成立」 | 性能、安全、公平、鲁棒性——全部必需 |
| Regression detection | 「一降就暂停」 | 当历史指标增量显示能力损失时暂停循环 |
| Kolmogorov bound | 「信息论极限」 | 限制系统能对自身后继者证明什么 |
| Lob's theorem | 「自指陷阱」 | 系统可以依据「我应当」行动，而无需证明自己应当 |
| Gate stack | 「分层检查」 | 多个原语组合；任何一项失败都拒绝该编辑 |
| Bounded improvement | 「缓解而非证明」 | 提高静默失败成本；不闭合安全问题 |
