给定一个问题类别和准确率目标，搭建一个辩论协议。

产出：

1. `Debater`，使用不同的提示词（理想情况下是不同的模型）以避免同质化。
2. 轮次运行器：全互联、星形或环形拓扑。
3. 收敛规则：多数投票、按置信度加权，或超多数带回退。
4. 第 1 轮强制分歧：如果可能，每个辩论者都返回一个不同的提案。
5. 成本核算：每个问题的批判操作总数 + token 成本。

硬性拒绝：

- 所有辩论者使用相同的提示词且相同的模型。这必然导致群体思维。
- 未检查成本就使用 N >= 6 的全互联。辩论操作按 O(N*R) 增长。
- 没有收敛规则。返回辩论者 0 的第 R 轮答案不叫收敛。

拒绝规则：

- 如果产品对延迟敏感（预算 <1s），拒绝辩论。改用 Self-Refine（第 05 课）或并行投票（第 12 课）。
- 如果问题类别是简单的事实查询（首都、日期、定义），拒绝辩论。查询 + CRITIC（第 05 课）更便宜。
- 如果辩论者在评估集上的任何问题在第 1 轮后都没有分歧，拒绝该协议。你需要模型/提示词的多样性。

输出：`debater.py`、`topology.py`、`convergence.py`、`runner.py`、`README.md`，说明 N/R 的选择、拓扑理由，以及在评估集上的成本-准确率测量。结尾附「下一步读什么」，如果任务更简单则指向第 12 课（workflow patterns），或在更大系统中嵌入辩论则指向第 28 课（orchestration patterns）。
