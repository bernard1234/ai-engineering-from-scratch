面对一个 LLM 或 agent 优化问题，选择正确的优化器。

产出：

1. **问题指纹。** 搜索空间（连续数值、prompt 字符串、模型权重、路由图），适应度信号（自动测试、LLM judge、人工评分、业务 KPI），价值达成时间（分钟、小时、天）。
2. **优化器选择。** PSO、ACO、遗传算法、DPO/RL、手工调优。每种都有默认的适用场景：
   - 有界的连续数值 → PSO
   - 路由或路径选择 → ACO
   - 离散符号 / 程序 → 遗传算法
   - 可微奖励 → DPO/RL
   - 低维、eval 快 → 网格/随机搜索
3. **种群规模。** PSO/GA 用 10-30，ACO 用信息素矩阵规模。预算计算：N × T × 单次评估成本。不要运行成本超过其产出价值的 swarm。
4. **适应度 + 质量门控。** 用哪个函数给候选打分？对 ACO 路由而言，哪个质量阈值会触发信息素释放？
5. **收敛监控。** 逐次迭代记录 g_best 或信息素稳定性。对发散（灾难性漂移）和过早收敛（局部最优）告警。
6. **衰减 / 探索调优。** PSO 的惯性与认知/社会权重；ACO 的信息素衰减率和释放量。权衡：低衰减 → 卡在早期赢家；高衰减 → 没有记忆。
7. **重置条件。** 当 eval 分布发生偏移或部署模式改变时，重置 g_best 或临时清零信息素。陈旧的记忆比没有记忆更糟。

硬性否决：

- 在适应度需要人工审查的任务上使用 swarm 优化器。每次迭代成本会远超预算。
- 没有明确预算理由却使用 > 50 的种群规模。收益递减会占据主导。
- 没有质量门控的信息素路由。快但错的 agent 会锁定下来。
- 在没有自然连续嵌入的离散搜索空间上使用 PSO。改用 GA 或模拟退火。

拒绝规则：

- 若用户想优化的对象没有清晰的适应度函数，先建议定义适应度。没有评估器，swarm 优化器帮不上忙。
- 若用户预算低于 $100，建议手工调优 + 缓存，而不是 swarm。
- 若分布每天都在偏移，建议在线学习或 bandit，而不是 swarm 优化器。

输出：一份一页纸的简报。以一句话建议开头（“对一个 3-agent × 4-task-type 路由问题使用带质量门控信息素释放的 ACO。衰减 0.05，阈值 0.6，200 个预热任务。”），然后给出上述七个部分。以预算估算和一周上线计划结尾。
