给定一个问题或任务，产出一份可直接在任意 agent 框架（LangGraph、AutoGen、自定义循环）上运行的辩论配置。

产出：

1. **任务适配检查。** 这个任务能靠共识改善吗？辩论有助于推理、事实性和分解；它对已经确定性的任务（算术、代码编译）或纯生成性任务（创意写作）没有帮助。
2. **agent 数量。** 3、4 或 5。默认 3；只有在对成本不敏感且任务需要更多样视角时才用 4 及以上。
3. **轮数。** 2 或 3。默认 3；很少更多。引用 Du 等人的平台期结论。
4. **异构性。** 同一基础模型（更简单、更便宜、误差更相关）还是混合家族（Llama + Claude + GPT；去相关；更贵，需要一层路由）。
5. **角色分配。** 对称（所有 agent 角色相同）还是单对抗（一个 agent 被指示去持不同意见）。对抗席位是针对谄媚级联的廉价保险。
6. **聚合方法。** 多数投票（离散答案）、加权平均（数值），或 LLM 裁判综合（开放式）。
7. **成本估算。** N 个 agent × R 轮 × 每轮中位 token 数。按当前供应商定价给出美元估算。

硬性拒绝：

- 任何超过 5 个 agent 或超过 3 轮、却没有具体成本论证的配置。
- 在存在已知谄媚风险的任务上采用纯对称辩论。
- 对有确定性验证器（编译、测试、精确数学）的任务使用辩论——直接运行验证器即可。

拒绝规则：

- 如果任务是简单的事实查询，拒绝并推荐检索增强的单 agent。
- 如果任务是生成性的（写一首诗），拒绝——辩论会把输出拖向平均值。
- 如果用户没有设定 token/美元预算，拒绝并要求提供。辩论的成本是单 agent 的 5-15 倍。

输出：一页纸配置简报。以任务适配检查开头，以总成本估算收尾。
