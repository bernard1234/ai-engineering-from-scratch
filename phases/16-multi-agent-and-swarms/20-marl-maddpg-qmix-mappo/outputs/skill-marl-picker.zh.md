面对一个 multi-agent 任务描述，挑选 MARL 算法。

产出：

1. **任务分类。** 完全合作（共享奖励）、完全竞争（零和）、混合、一般和。agent 数量。同质 vs 异质。
2. **可观测性。** 完全（每个 agent 看到全局状态）、部分（各自只看到自身观测），或启用了通信。
3. **动作空间。** 离散（类 Atari、SMAC）或连续（particle world、MuJoCo）。影响算法选择。
4. **奖励结构。** 稠密（逐步塑形）vs 稀疏（仅终止时）。稠密让 MAPPO 可行；稀疏需要信用分配的辅助（QMIX 的价值分解）。
5. **算法推荐。** 按 Yu 等 2022，以 MAPPO 作为 baseline 起步。切换到：
   - 当合作 + 同质 + 需要强稀疏奖励信用分配时，用 QMIX
   - 当混合（合作 + 竞争）+ 连续动作时，用 MADDPG
   - 当单调性约束过于苛刻时，用扩展（QTRAN、QPLEX、FACMAC）
6. **训练基础设施。** 你是否具备：足够的交互数据、算力预算、奖励塑形专业能力、稳定性预算（每个实验 5-10 个随机种子）？若不具备，为 LLM agent 推荐 prompt 层面的策略。
7. **部署契约。** CTDE：部署时每个 agent 只看到局部观测。把契约明确写出来，好让运行时代码遵守它。

硬性否决：

- 首次运行就选非 MAPPO 的 baseline。MAPPO 是 2026 年的 baseline；从它开始。
- 对混合合作-竞争任务使用 QMIX。价值分解假定单调聚合。
- 为缺乏交互数据或奖励信号的 LLM-agent 系统推荐 MARL 训练。在数据到位之前，prompt 层面的策略会表现更好。
- 训练时不记录每个 agent 的观测和动作。调试将无法进行。

拒绝规则：

- 若任务的交互数据少于约 1000 个 episode，推荐 prompt 层面的策略或有监督微调。
- 若任务是非马尔可夫的（需要记忆）而推荐里没有循环 critic，标出这一缺口。
- 若任务是一般和竞争（存在多个均衡），单靠 MARL 无法选出其中一个；推荐机制设计或均衡选择。

输出：一份一页纸的简报。以一句话建议开头（“MAPPO baseline + 集中式价值函数；每个 agent 一个离散 actor；部署时采用 CTDE；每个实验 5 个随机种子。”），然后给出上述七个部分。以从训练到部署的流水线结尾：数据收集、训练、评估、上线。
