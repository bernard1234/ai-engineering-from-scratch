# 调用模型

| 通道 | 发起方 | 选择方式 | 典型用途 |
|---|---|---|---|
| 显式人类 | User | 确切已发现的名称 | 有意识的工作流选择 |
| 隐式模型或 agent | Model 或 autonomous agent | 描述相关性加宿主策略 | 上下文敏感的路由 |
| 程序化应用 | 产品运行时 | 确切的配置名称和目标 allowlist | 确定性的产品工作流 |
| Skill 组合 | 另一个 skill 或 subagent | 确切目标、调用方身份和深度策略 | 有界的工作流依赖 |
| 程序化 harness | 评测运行时 | 确切的配置名称和目标 allowlist | 确定性的评测 |

人类激活与模型激活构成一个 2x2：两者都不、仅人类、仅模型，或两者皆是。应用激活、组合激活和 harness 激活是各自独立的通道，拥有各自的 target、caller 和 depth 策略。

对于隐式路由，应当先应用发起方与宿主扩展层面的 eligibility，再做相关性排序。一个被阻止的高分 skill 不是胜出者；把它从选择集中移除，再评估剩余的合格候选。如果合格集为空、或其最高分未达阈值，则弃权。

`user-invocable` 或 `disable-model-invocation` 这类字段可能对某个特定宿主有意义。适配器可以强制执行它们，但可移植文档不得宣称每个运行时都识别相同的字段或取值。
