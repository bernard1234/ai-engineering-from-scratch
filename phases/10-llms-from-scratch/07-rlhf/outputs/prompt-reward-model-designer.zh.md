# Reward Model 设计器

当你构建 RLHF 流水线、把语言模型对齐到目标行为（有用性、编程能力、安全、诚实）时，用这个框架设计数据采集协议、训练 reward model 并配置 PPO。

## 输入要求

请提供：
- **目标行为**（例如 "helpful and harmless assistant"、"expert Python coder"、"medical Q&A with safety"）
- **基础模型**（例如 SFT 后的 Llama 3 8B、Mistral 7B Chat）
- **Reward model 规模**（通常与 policy model 同规模或更大）
- **标注预算**（可用的人工工时或对比对数量）
- **算力预算**（reward model 训练 + PPO 的 GPU 小时数）

## 第 1 步：偏好数据采集

### 标注协议

1. **Prompt 选择**：从 SFT 训练分布以及分布外 prompt 中采样（10-20% 为新 prompt）
2. **回答生成**：用 SFT 模型以不同 temperature（0.3、0.7、1.0）为每个 prompt 生成 2-4 个回答
3. **比较格式**：向标注者展示恰好 2 个回答，问 "Which response is better?"
4. **评分细则**：为你的用例定义 "better" 的含义

### 评分细则模板

| 标准 | 权重 | 描述 |
|-----------|--------|-------------|
| 有用性 | 40% | 是否完整且正确地回答了问题？ |
| 无害性 | 25% | 是否避免了有害、有偏见或误导性内容？ |
| 诚实性 | 20% | 是否承认不确定性而不是编造？ |
| 简洁性 | 15% | 回答长度是否与问题相称？ |

针对你的用例调整权重。编程助手可以把正确性权重设为 60%，简洁性设为 20%。

### 数据规模指南

| 规模 | 对比对数量 | 标注者工时 | 预期 RM 准确率 |
|-------|-----------------|-----------------|---------------------|
| 最小可用 | 5,000-10,000 | 400-800 | 60-65% |
| 生产 v1 | 20,000-50,000 | 1,600-4,000 | 65-72% |
| 生产 v2 | 100,000-500,000 | 8,000-40,000 | 72-78% |

InstructGPT 使用了来自 40 名承包商的 33,000 组比较。Anthropic 的初始论文使用了来自 20 名标注者的 22,000 组。标注者间一致性通常在 70-75% —— reward model 不可能超过人类一致性水平。

### 质量控制

- **一致性过滤**：丢弃同意率低于 70% 的对比对
- **标注者校准**：正式标注前，用已知优质的对做校准轮次
- **偏差检测**：监控标注者是否一致偏好更长的回答、更正式的语言或特定模式
- **对抗样本**：加入 5-10% 专门设计的样本，用来抓住没有仔细阅读的标注者

## 第 2 步：Reward Model 架构

### 架构决策

| 决策 | 建议 | 理由 |
|----------|---------------|-----------|
| 基础架构 | 与 policy 相同的 transformer | 从 SFT checkpoint 初始化权重，起始特征更强 |
| 输出头 | 从最后 hidden state 做单个线性投影 | 从最完整的位置表示得到标量 reward |
| 模型规模 | >= policy model 规模 | 更小的 RM 会产生不可靠的信号，使 PPO 不稳定 |
| 初始化 | SFT checkpoint + 新的输出头 | 预训练特征已经捕捉了语言质量 |

### 训练配置

| 参数 | 范围 | 说明 |
|-----------|-------|-------|
| 学习率 | 1e-5 到 5e-5 | 比 SFT 低，因为任务更简单 |
| Epochs | 1-3 | 对比数据有限时，过拟合是主要风险 |
| Batch size | 64-256 | 每个 "example" 是一对，因此有效数据量是 2 倍 |
| 损失函数 | Bradley-Terry：-log(sigmoid(r_preferred - r_rejected)) | 成对比较的标准做法 |
| 验证集比例 | 10-20% | 监控留出对上的准确率 |

### 评估指标

1. **成对准确率**：RM 在留出偏好对上排序正确的比例。目标：> 65%
2. **margin 分布**：绘制 (r_preferred - r_rejected) 的分布。应以 0 以上为中心，负值很少。
3. **校准**：sigmoid(r_preferred - r_rejected) 是否接近实际的人类偏好概率？
4. **分布外泛化**：在与训练不同分布的 prompt 上测试。准确率下降应 < 10%。

## 第 3 步：PPO 配置

### 超参数

| 参数 | 典型值 | 过高的影响 | 过低的影响 |
|-----------|--------------|-------------------------|------------------------|
| KL 系数（beta） | 0.01-0.05 | 模型几乎学不到东西，过于贴近 SFT | Reward hacking，输出退化 |
| 学习率 | 5e-6 到 3e-5 | 训练不稳定、发散 | 收敛慢，浪费算力 |
| Clip 比例（epsilon） | 0.1-0.3 | 更新幅度大，可能破坏稳定性 | 更新过于保守，学习缓慢 |
| 每 batch 的 PPO epochs | 1-4 | 对当前 batch 过拟合 | 未充分利用每个 batch |
| 生成 batch size | 128-512 | 内存问题 | 梯度估计噪声大 |
| 最大回答长度 | 256-1024 | 生成慢，内存问题 | 截断有用的回答 |

### 监控看板

在 PPO 训练期间跟踪这些指标：

1. **平均 reward**：应随训练上升。持平没问题；下降意味着不稳定。
2. **KL 散度**：应保持在 10-20 nats 以下。突增 = reward hacking。
3. **回答长度**：应保持稳定。单调上升 = 冗长性 reward hacking。
4. **熵**：token 分布熵应缓慢下降。快速下降 = 模式崩溃。
5. **Reward model 一致性**：用 reward model 给 PPO 的回答打分；一致性应改善。

### PPO 期间的危险信号

| 症状 | 可能原因 | 修复 |
|---------|-------------|-----|
| Reward 上升但输出退化 | Reward hacking | 提高 KL 系数，用对抗样本重新训练 RM |
| KL 散度爆炸 | 学习率过高或 KL 系数过低 | 降低 lr，提高 beta |
| 回答长度单调增长 | RM 奖励冗长 | 在 reward 中加入长度惩罚，用长度受控的对重新训练 RM |
| 所有回答变得一模一样 | 模式崩溃 | 提高生成 temperature，减少 PPO epochs |
| Reward 剧烈震荡 | PPO 不稳定 | 降低学习率，提高 clip 比例 |

## 第 4 步：端到端验证

部署 RLHF 训练的模型之前：

1. **与 SFT 做 A/B 测试**：在 200+ 个测试 prompt 上运行 SFT 模型和 RLHF 模型。让 3 名以上评估者比较回答。RLHF 模型应在 60% 以上的情况下胜出。
2. **安全评估**：在已知对抗 prompt（jailbreak、有害请求）上测试。RLHF 模型应恰当地拒绝。
3. **回归检查**：运行标准 benchmark（MMLU、HumanEval、MT-Bench），确认 RLHF 模型没有丢失核心能力。
4. **遗忘检查**：在通用文本语料上测量 perplexity。相对 SFT 模型的上升应 < 10%。
5. **长度分析**：比较 SFT 与 RLHF 模型的平均回答长度。如果 RLHF 长 50% 以上，reward model 很可能有冗长偏差。
