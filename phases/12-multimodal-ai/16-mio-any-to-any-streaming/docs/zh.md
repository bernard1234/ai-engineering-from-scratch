# MIO 与任意到任意的流式多模态模型

> GPT-4o 交付了一个大多数开源模型无法复刻的产品：一个能听语音、看视频并实时说回来的 agent。到 2024 年底，开源生态给出的答案是 MIO（Wang 等，2024 年 9 月）。MIO 把文本、图像、语音和音乐都 token 化，在交错序列上训练一个因果 transformer，并实现任意模态到任意模态的生成。AnyGPT（Zhan 等，2024 年 2 月）是概念验证；MIO 是规模化版本；Unified-IO 2（Allen AI，2023 年 12 月）则是带有视觉 + 动作定位的表亲。本节课解读任意到任意这一模式——四个 tokenizer，一个 transformer，对流式友好的解码。

**Type:** Learn
**Languages:** Python（标准库，四模态 token 分配器 + 流式解码循环）
**Prerequisites:** Phase 12 · 11（Chameleon）、Phase 6（语音与音频）
**Time:** ~120 分钟

## Learning Objectives

- 设计一个共享词表，能容纳文本、图像、语音与音乐 token 而不发生碰撞。
- 比较 SEED-Tokenizer（图像）与 SpeechTokenizer 的残差 VQ（语音）在压缩与重建之间的权衡。
- 解释构建任意到任意生成能力的四阶段训练课程。
- 说出三种开源任意到任意的配方及其主要权衡：MIO、AnyGPT、Unified-IO 2。

## 问题场景

统一多模态模型喊起来容易，但要规模化建起来很难。2024 年之前，大多数"任意到任意"系统都是流水线式的：视觉模型 → 文本表示 → 语音模型 → 音频。每次跳转都会丢失信息、增加延迟并使训练复杂化。GPT-4o 的演示视频展示了一种单模型替代方案，响应时间在亚秒级；开源系统落后了数月。

工程上的挑战：

- 每种模态都必须有对应的 tokenizer，且压缩要足够无损以支持重建，token 产出速率又要是 transformer 能消费的。
- 单一词表必须为文本（32k+）、图像（16k+）、语音（4k+）、音乐（8k+）分配空间。至少四万多个条目。
- 训练数据必须覆盖每一组输入-输出对（文本→图像、图像→语音、语音→图像等），否则模型必须具备组合能力。
- 推理时必须足够快地流出输出 token，以满足对话延迟（首个音频字节时间 <500ms）。

## 核心概念

### 四种模态，四个 tokenizer

MIO 的 tokenizer 栈：

- 文本：标准 BPE，词表约 32000。
- 图像：SEED-Tokenizer（2023）——带离散码本的量化 VAE，4096 条目，每张图像 32x32 个 token。
- 语音：SpeechTokenizer 残差 VQ（2023）——把 16kHz 波形编码为 8 个分层码本；第一层是粗粒度内容，后续层叠加韵律与说话人身份。
- 音乐：类似的残差 VQ（Meta 的 MusicGen / Encodec 系列），4-8 个码本。

每种模态都产出整数 token。这些 token 在共享词表中获得互不相交的 ID 区间：

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

总计约 48k 词表。输入 embedding 与输出投影都覆盖其全部范围。

### 流式解码

语音生成使用残差 VQ。transformer 预测基础层（第 0 层）语音 token；一个并行解码的残差量化器预测后续层。在 16kHz 下，每个第 0 层 token 大约对应 50ms 音频。

流式流程如下：

1. 用户对着麦克风说话；实时音频 tokenizer 每 50ms 输出一次语音 token。
2. MIO 在 token 到达时即消费（prompt prefill + 增量前向）。
3. 输出 token 随生成流出；一个并行语音解码器把它们转换成音频采样，延迟约 50-150ms。
4. 首个音频字节时间：MIO 论文中约 300-500ms，逼近 GPT-4o 的约 250ms。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）与 Moshi（arXiv:2410.00037）是互补的流式语音 LLM 设计。Moshi 尤其做到在单张 GPU 上 160ms 往返。

### 四阶段课程

MIO 的训练课程：

1. 第 1 阶段 —— 对齐。大规模模态对语料：文本-图像、文本-语音、文本-音乐。每一对使用各自在词表中的 token 区间。训练共享词表。
2. 第 2 阶段 —— 交错。多模态交错文档（含图像 + 视频的博客、带文字稿的播客等）。训练跨模态上下文。
3. 第 3 阶段 —— 语音增强。额外音频数据，在不损失文本能力的前提下提升语音质量。
4. 第 4 阶段 —— SFT。跨模态指令微调：VQA、图像描述、旁白解说、语音到语音对话。

缺失某个阶段会削弱特定能力：跳过第 2 阶段，模型就丢失跨模态上下文；跳过第 3 阶段，语音质量会很差。

### 视觉思维链

MIO 引入了 chain-of-visual-thought：模型把中间图像 token 作为推理步骤输出。对于"猫在爬树吗？"这类问题，模型会：

1. 输出 `<image>` token，渲染出场景（基于输入图像或草图）。
2. 输出文本，分析该草图。
3. 输出最终答案。

渲染出的中间图像充当草稿纸。空间推理类任务的 benchmark 因此提升。这一思路与文本推理中的 chain-of-thought 相呼应。

### 任意到任意领域的竞争者

- AnyGPT（arXiv:2402.12226）：4 种模态（文本、图像、语音、音乐），设计类似。
- Unified-IO 2（arXiv:2312.17172）：增加视觉动作输出、深度、法线。任务多样性更高，规模更小。
- NExT-GPT（arXiv:2309.05519）：LLM + 各模态专属 diffusion 解码器。不是单模型方案。
- CoDi（arXiv:2305.11846）：可组合 diffusion；通过共享潜空间实现任意到任意。

MIO 最接近纯 token 的任意到任意。AnyGPT 是它的概念先驱。

### 延迟预算

对于对话式产品，每个组件的延迟都很重要：

- 麦克风到音频 token：约 50ms。
- Prefill（音频 token + 历史）：8B 模型上约 100ms。
- 首个输出 token：约 50ms。
- 并行残差 VQ + 语音解码器：约 100-150ms。

首个音频字节总时间：最低约 300ms。GPT-4o 声称约 250ms。Moshi 声称 160ms。按公开 benchmark，MIO/AnyGPT 处于 400-600ms 区间。

### 为什么任意到任意依然很难

即便到了 2026 年，开源任意到任意模型在两个维度上仍落后于闭源模型：

- 语音质量。残差 VQ tokenizer 是有损的；与 ElevenLabs 级别的声音相比，对话语音听起来很机械。
- 跨模态推理。让模型"唱唱你所看到的"仍然比纯视觉任务更容易失败。

这些是开放的研究问题。Qwen3-Omni（第 12.20 课）是 2025 年最先进的开源尝试。

## Use It

`code/main.py`：

- 定义四模态的词表分配并打印出来。
- 把一组多模态输入（文本、图像、音频片段、音乐）通过 tokenizer 路由器分发。
- 模拟文本到语音回复的流式解码并统计延迟。
- 在给定编码器、prefill 与解码器延迟的情况下，计算预期的首个音频字节时间。

## Exercises

1. 你的产品接受语音输入并返回语音输出。端到端延迟预算目标定多少？列出会消耗时间的各个组件。

2. SpeechTokenizer 的残差 VQ 使用 8 个码本。请论证为什么必须对残差各层做并行解码（而非串行），以及它带来多少延迟节省。

3. 你的词表包含 32k 文本 + 4k 图像 + 4k 语音。再加上 8k 音乐与约 10 个分隔符。在隐层维度 4096 下，embedding 矩阵的参数开销是多少？

4. 视觉思维链会输出一张中间图像。什么样的任务受益？什么样的任务会因额外的 token 而受损？

5. 阅读 Moshi（arXiv:2410.00037）。描述它的"inner monologue"技术，并与 MIO 的 chain-of-visual-thought 作比较。

## Key Terms

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------------|------------------------|
| 任意到任意 | “多模态输入/输出” | 单一模型可接受并输出文本、图像、语音与音乐，且方向任意 |
| 残差 VQ | “语音 tokenizer 栈” | 多码本 token 化，每层叠加信息；基础层是内容，后续层是韵律 |
| SEED-Tokenizer | “图像编码” | MIO 使用的、带 4096 条目码本的离散图像 tokenizer |
| 视觉思维链 | “视觉草稿纸” | 模型在给出最终答案前生成一张中间图像作为推理步骤 |
| 首个音频字节时间 | “TTFAB” | 从用户开口到首个音频输出的延迟；对话级体验需 <500ms |
| 四阶段课程 | “训练配方” | 对齐 -> 交错 -> 语音增强 -> SFT，按此顺序 |
