# LLaVA-OneVision：单图、多图、视频共用一个模型

> 在 LLaVA-OneVision（Li 等，2024 年 8 月）之前，开放 VLM 世界有几条各自独立的谱系：用于单图的 LLaVA-1.5，用于多图的 Mantis 和 VILA，用于视频的 Video-LLaVA 和 Video-LLaMA。每一个都在自己的 benchmark 上取胜，却在其他场景上失败。LLaVA-OneVision 主张，单一课程就能训练出一个模型，同时统治这三种场景，而且涌现出的任务迁移效应（单图技能迁移到视频，多图推理迁移到单图）胜过专家的总和。这套配方乍看简单：一个在各场景间保持恒定的视觉 token 预算，外加一条从单图到 OneVision（多图）再到视频的显式课程。本节课研读这个预算、这条课程，以及这些涌现行为。

**Type:** 构建
**Languages:** Python（标准库，token 预算求解器 + 课程规划器）
**Prerequisites:** Phase 12 · 05（LLaVA）、Phase 12 · 06（任意分辨率）
**Time:** ~180 分钟

## Learning Objectives

- 设计一个在单图、多图和视频输入之间保持恒定的视觉 token 预算。
- 安排一条训练课程，把技能从单图迁移到视频，且不出现灾难性遗忘。
- 解释在参数量相同时，若课程设计得当，为什么单一模型能胜过专家模型。
- 说出 LLaVA-OneVision 报告的三项涌现能力：多摄像头推理、set-of-mark 提示、iPhone 截图 agent。

## 问题场景

图像、多图和视频对模型的压力各不相同。

单图需要高分辨率 token（AnyRes，约 2880 个视觉 token）来捕捉 OCR 和细节。每样本预算：一张图，2880 token。

多图需要多张中等分辨率的图像（每张约 576 token），这样跨图推理才能装进上下文。每样本预算：4-8 张图，每张 576，共 2300-4600 token。

视频需要大量低分辨率帧（池化后每帧约 196 token）来捕捉时序动态。每样本预算：8-32 帧，每帧 196，共 1600-6200 token。

如果你训练独立模型，你就选定一种预算。如果你训练单一模型，你就需要让预算在各场景间合理伸缩，而不撑爆上下文。

在 OneVision 之前，默认答案是「训练一个场景，忽略其他」。Video-LLaVA 用额外的训练阶段把视频嫁接在图像模型上。LLaVA-NeXT 用切块加入多图支持。没有一个能干净地处理全部三种。

## 核心概念

### OneVision 的 token 预算

LLaVA-OneVision 选择一个统一的视觉 token 预算，约每样本 3000-4000 个 token，并按场景不同而分配：

- 单图：AnyRes-9（3x3 切块 + 缩略图），每个切块 384 分辨率、729 个 patch，2x2 的激进双线性池化 → 每块 182。总计：9 * 182 + 182 = 1820 token。或者 AnyRes-4，每块 729 = 2916 + 729。
- 多图：每张图中等分辨率（384，不切块），729 token，不做池化。预算 6 张图 → 4374 token。
- 视频：32 帧、384 分辨率，配合激进的 3x3 双线性池化 → 每帧 81 token。总计：32 * 81 = 2592 token。

这种分配让 token 总数大致保持恒定。LLM 永远不会看到一个撑爆其上下文的 batch。编码器在每个场景下产出不同的几何结构，但 LLM 消费的是同一份预算。

### 三阶段课程

LLaVA-OneVision 分三个阶段训练：

1. 单图 SFT（stage SI）。所有数据都是单图 + 文本。在高分辨率的 AnyRes 输入上训练。这一步教授感知、OCR 和细粒度理解。使用 LLaVA-NeXT 数据加上 OneVision 特有的单图数据。
2. OneVision SFT（stage OV）。混合单图 + 多图 + 视频（均匀采样帧）。在统一的 token 预算上训练。这一步教模型处理异构的 batch 形状。不重置权重——从 stage SI 继续。
3. 任务迁移（stage TT）。以目标任务组合继续，通常根据产品情况更偏重多图或视频。部署前可选微调。

关键：课程顺序很重要。先训练视频或先训练多图，得到的图像性能都比先训练单图更差，即使数据相同。论文对此做了明确的消融。

### 课程为什么有效

单图训练建立起感知底座。patch token 携带细粒度的视觉特征；LLM 学会把它们与文本整合。多图和视频引入了结构性挑战（哪张是哪张、什么先发生），没有强感知底座就很难学会。

如果你从零开始一起训练所有场景，模型会欠拟合感知（每 batch 单图数据有限），同时过拟合结构（大量多图 / 视频数据）。结果：一个能遵循跨图推理模式、但视觉上很浅的模型。

课程排序让你从 stage SI 获得感知能力，再从 stage OV 获得组合/时序推理，两者都不丢失。

### 跨场景的涌现技能

LLaVA-OneVision 论文报告了三项涌现能力：

1. 多摄像头推理。分别在多图 + 视频上训练；推理时被要求对一个多摄像头驾驶场景进行推理。模型正确地整合了各视角，尽管训练中从未见过那种确切格式。
2. Set-of-mark 提示。用户在图像中的物体上标注带编号的标记；模型推理「标记 3 相对于标记 7 在做什么」。既未在标记上训练，也未在标注上训练；它是从空间 grounding + 多图引用这两者的组合中学到的。
3. iPhone 截图 agent。用户提供一张 iPhone 屏幕的截图，要求规划下一次点击。训练数据包含 UI 截图、用户工作流的视频，以及多图前后对比对。它能泛化到这个 agent 用例。

这些不是训练过的任务；它们从课程的组合结构中涌现出来。

### 视觉 token 池化

这份 token 预算要求池化。OneVision 在 2D patch 网格上使用双线性插值：24x24 = 576 个 patch 变成 12x12 = 144（2 倍系数）或 8x8 = 64（3 倍系数）。池化在 patch 网格空间中进行，而非 token 空间，以保持局部性。

每个场景的池化系数本身就是超参数。池化越少 = token 越多 = 表示越丰富。池化越多 = token 越少 = 能装下更多帧 / 图像。

### LLaVA-OneVision-1.5

2025 年的后续工作（LLaVA-OneVision-1.5，arXiv 2509.23661）在训练数据、模型权重和代码上都是「完全开放」的。在某些 benchmark 上追平了与专有模型的差距，并让这套配方大众化。同样的课程，更多数据，更好的基础 LLM。架构没有变化。

### 与 Qwen2.5-VL 的对比

Qwen2.5-VL（第 12.09 课）做出了不同的选择。它用 M-RoPE 和动态 FPS，而不是固定池化。它的预算随输入伸缩——1 分钟视频用的 token 比 5 秒视频更多。LLaVA-OneVision 固定预算、调整池化。两种方式都可行；它们用可配置性换取可预测性。

## Use It

`code/main.py` 是一个 OneVision 风格 VLM 的课程与预算规划器。给定每样本的 token 预算和目标场景组合（比如 40% 单图、30% 多图、30% 视频），它会：

- 分配各场景的分辨率、池化系数和帧数。
- 检查每个场景是否都在共享预算之内。
- 报告预期 token 数、LLM FLOPs，以及哪些场景 token 不足。
- 打印逐阶段的训练日程。

用它来规划一次 OneVision 微调，或者核算某个 VLM 部署的每请求成本。

## Ship It

本节课产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每样本预算，它会输出 AnyRes 系数、每帧池化、视频帧数以及课程阶段权重。每当你训练或微调一个统一场景的 VLM 时都可以用。

## Exercises

1. 你的产品支持 80% 单图、10% 多图（2-4 张）、10% 视频（8-16 帧）。设计 token 预算。你会把因为不做繁重多图而省下的额外预算放在哪里？

2. 阅读 LLaVA-OneVision 第 4.3 节（涌现能力）。提出第四项课程很可能解锁、但论文没有报告的涌现技能。

3. 交换课程顺序——先训练多图，再单图，然后视频。预测哪些 benchmark 会退化，以及为什么。

4. 论文报告的视频 benchmark 每样本只用 8 帧训练。这能泛化到推理时的 30 秒视频吗？先崩掉的是什么——token 预算还是时序推理？

5. 把 24x24 的 patch 双线性池化到 12x12，每个维度是 4 倍缩减。用标准库 Python 实现这个池化，并验证每个 2x2 块上的均值与双线性输出一致。

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| OneVision scenario | 「单图、多图或视频」 | 统一 VLM 处理的三种输入形态之一；预算在其间保持恒定 |
| Token budget | 「每样本多少 token」 | LLM 每个训练 / 推理样本看到的视觉 token 总量，通常 3000-4000 |
| Curriculum | 「训练顺序」 | 为涌现式迁移而选择的阶段顺序（单图 → 多图 → 视频） |
| Bilinear pooling | 「token 压缩」 | 在 patch 网格（2D）上做双线性插值以减少 token 数，同时保持局部性 |
| Emergent skill | 「没训练过，却能用」 | 由于课程组合而在推理时出现、并无对应训练数据的能力 |
| AnyRes-k | 「k 切块设置」 | k 个固定分辨率的子切块加一张缩略图，k 通常 ∈ {4, 9} |
| Task transfer | 「跨场景泛化」 | 通过共享骨干网络，在单图上学到并适用于视频（反之亦然）的技能 |
