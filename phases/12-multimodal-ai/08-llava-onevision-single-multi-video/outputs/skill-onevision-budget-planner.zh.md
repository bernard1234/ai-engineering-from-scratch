给定产品的预期任务分布——单图、多图和视频请求各自的百分比——以及每样本视觉 token 预算，输出一份逐场景分配方案和一条训练课程。

产出：

1. 逐场景配置。单图：AnyRes 切块数 + 缩略图 + 池化系数；多图：每样本图像数 + 每图池化；视频：帧数 + 每帧池化。
2. Token 预算平衡。每个场景的 token 总量应落在目标预算的 ±30% 之内；标记任何低于目标 70%（token 不足）或高于 130%（上下文风险）的场景。
3. 课程计划。三个阶段（SI → OV → TT），并给出数据权重。TT 阶段使用用户的产品组合。
4. 预期涌现技能。根据用户的产品组合，预测哪些 LLaVA-OneVision 风格的涌现能力可能出现（多摄像头、set-of-mark、截图 agent，或产品特定的变体）。
5. 训练数据量级估算。在 7B 基础 LLM 的前提下，给出每阶段大致需要的 token / 图像 / 帧数，并引用 OneVision-1.5 的数据规模。

必须拒绝：
- 提出把视频或多图排在单图之前的阶段顺序。OneVision 表明这会损失 2-4 分 MMMU。
- 在产品 80% 为单图的情况下把所有预算都分配给视频。那是浪费，不是平衡。
- 假设 AnyRes-16（4x4 网格）在不做激进池化的情况下能装进 4k token 预算。它装不进。

拒绝规则：
- 如果每样本 token 预算低于 1024，对多图或视频用例拒绝——低于这条底线，场景会崩掉。
- 如果用户想要 5 帧以上、每帧满 729 token 分辨率的视频，拒绝；建议 3 倍池化或减少帧数。
- 如果产品分布完全不含单图，拒绝，改为建议 Qwen2.5-VL 风格的 M-RoPE——OneVision 的课程把单图作为感知底座。

输出：一份单页方案，含逐场景 token 配置、课程阶段权重、涌现技能预测以及数据规模估算。结尾给出指向 arXiv 2408.03326 (OneVision) 与 arXiv 2509.23661 (OneVision-1.5 完全开放) 的指引。
