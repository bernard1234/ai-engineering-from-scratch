# 分类基线指南

在尝试复杂模型之前，先用逻辑回归建立一个基线。它几秒就能训练完，能输出概率，而且完全可解释。令人惊讶的是，很多真实问题永远不需要更花哨的东西。

## 决策检查清单

1. 决策边界可能是线性的吗？
   - 是：逻辑回归很可能就足够了
   - 否：你还是想用它做基线来衡量提升

2. 你有多少特征？
   - 不到 50：标准逻辑回归就够用
   - 50 到 10,000：加 L2 正则化（Ridge）
   - 超过 10,000（比如 TF-IDF 文本特征）：用 L1 正则化（Lasso）或 LinearSVC

3. 数据集不平衡吗？
   - 比例在 5:1 以内：可能不需要调整
   - 5:1 到 50:1：在 sklearn 里用 `class_weight="balanced"`
   - 超过 50:1：结合类别加权和合适的指标（精确率、召回率或 F1）

4. 特征尺度不同吗？
   - 逻辑回归之前一定要标准化。它用基于梯度的优化，未经缩放的特征会减慢收敛或扭曲决策边界。

5. 有缺失值吗？
   - 拟合前先填充。逻辑回归处理不了 NaN。
   - 数值列用中位数填充，类别列用众数。

## 什么时候逻辑回归就够用了

- 二分类，特征关系大部分线性
- 你需要概率输出（不只是类别标签）
- 需要可解释性（标准化后的系数能指明特征重要性方向和相对大小）
- 训练数据小（几百到几千样本）
- 需要快速模型用于实时推理（推理时就是一次点积）
- 监管或合规要求可解释性

## 什么时候该升级

- 准确率在远低于目标处停滞，且你已经尝试过特征工程
- 特征和目标的关系明显非线性（检查残差图）
- 你有大量表格数据（10k+ 行）：试试梯度提升（XGBoost 或 LightGBM）
- 特征有多项式特征无法捕获的复杂交互
- 你有图像、文本或序列数据：在原始输入上用逻辑回归不行

## 分类基线的预处理步骤

1. **先做训练/测试划分**，在任何预处理之前。这能防止数据泄露。
2. **处理缺失值**：数值列中位数填充，类别列众数填充。
3. **编码类别**：低基数（不到 10 个值）用 one-hot，更高的用目标编码。目标编码只在训练折上拟合（用 out-of-fold 编码防泄露）。
4. **缩放数值列**：StandardScaler（零均值、单位方差）。在训练集上拟合，然后对两者都 transform。
5. **拟合逻辑回归**，用 `C=1.0`（默认正则化）。
6. **评估**：混淆矩阵、精确率、召回率、F1。不要只看准确率。
7. **调阈值**：默认 0.5 很少是最优的。从 0.1 到 0.9 扫描，选一个匹配你精确率/召回率优先级的阈值。

## 常见错误

- 不平衡数据上只评估准确率（永远预测多数类的模型得分很高但毫无用处）
- 忘了缩放特征（用未缩放特征训练的逻辑回归训练慢，且收敛到更差的解）
- 用测试集调决策阈值（应该用验证集或交叉验证）
- 跳过基线直接上 XGBoost（你失去了可解释性，也没有参考基准）
- 不检查多重共线性（高度相关的特征会放大系数方差）

## 快速参考

| 场景 | 模型 | 正则化 | 关键设置 |
|------|------|--------|----------|
| 少特征，可解释 | LogisticRegression | L2（默认） | C=1.0 |
| 多特征，部分无关 | LogisticRegression | L1 | penalty="l1", solver="saga" |
| 高维稀疏（文本） | SGDClassifier | L1 或 ElasticNet | loss="log_loss" |
| 类别不平衡 | LogisticRegression | L2 | class_weight="balanced" |
| 需要概率 | LogisticRegression | L2 | predict_proba() |
| 只要类别标签 | LinearSVC | L2 | 大数据时比 LR 更快 |
