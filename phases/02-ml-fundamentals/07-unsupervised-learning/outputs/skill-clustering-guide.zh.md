# 聚类算法选择指南

聚类没有单一的最好算法。合适的选择取决于簇的形状、你是否知道簇的数量、数据里有多少噪声，以及数据集有多大。

## 决策检查清单

1. 你知道簇的数量吗？
   - 是：K-Means 或 GMM
   - 否：DBSCAN（自动发现簇），或层次聚类（在不同高度切树状图）

2. 簇是什么形状？
   - 大致球形（团状）：K-Means
   - 有不同大小的椭圆形：GMM
   - 任意形状（月牙、环形、链）：DBSCAN
   - 嵌套或层次结构：层次聚类

3. 数据有噪声或异常值吗？
   - 有：DBSCAN（显式标记噪声点）或 GMM（低概率点是异常值）
   - 没有：K-Means 就可以

4. 你需要软分配（概率）吗？
   - 是：GMM 给出每个簇的 P(cluster | data point)
   - 否：K-Means 或 DBSCAN 给出硬分配

5. 数据集有多大？
   - 不到 10,000：任何算法都行
   - 10,000 到 1,000,000：K-Means（快）、Mini-Batch K-Means（更快）
   - 超过 1,000,000：Mini-Batch K-Means 或 BIRCH。层次聚类太慢了。

## 何时用每种方法

**K-Means**：默认起点。快（O(n * k * iterations)）、简单，很多问题够用。用肘部法或轮廓分数选 K。局限：假设球形簇，对初始化敏感（用 K-Means++ 或多跑几次），不能很好处理簇大小差异。

**DBSCAN**：发现任意形状的簇和自动检测异常值的最佳选择。两个参数：eps（邻域半径）和 min_samples（最小密度）。不需要指定 K。局限：簇密度差异很大时困难，调 eps 可能棘手。用 k-距离图估计 eps：算每个点到它第 k 个最近邻的距离，排序后找肘部。

**层次聚类（自底向上）**：构建一棵合并的树。当你想在多个粒度上探索簇结构时用（在不同高度切树状图）。Ward linkage 对紧凑簇最好。Single linkage 找拉长的簇但对噪声敏感。局限：O(n²) 内存，O(n³) 时间，大数据集不实际。

**GMM（高斯混合模型）**：带概率分配的软聚类。把每个簇建模成有自己均值和协方差的高斯分布。簇是椭圆或重叠时比 K-Means 好。用 BIC（贝叶斯信息准则）选组件数量。局限：假设高斯分布，非凸形状会失败，对初始化敏感。

## 评估簇质量（无标签）

| 指标 | 衡量什么 | 范围 | 何时用 |
|------|----------|------|--------|
| Silhouette score | 凝聚度 vs 分离度 | -1 到 1（越高越好） | 比较 K 值或算法 |
| Inertia（簇内 SS） | 簇的紧凑度 | 0 到 ∞（越低越好） | K-Means 的肘部法 |
| BIC / AIC | 带复杂度惩罚的模型拟合 | 越低越好 | 选 GMM 组件数量 |
| Calinski-Harabasz index | 簇间 vs 簇内方差比 | 越高越好 | 快速比较 |
| Davies-Bouldin index | 簇间平均相似度 | 越低越好 | 惩罚重叠簇 |

## 常见错误

- 跑 K-Means 不缩放特征（尺度大的特征主导距离计算）
- 实际数据是高维时靠 2D 视觉看数据来选 K（用轮廓分数）
- 非球形簇上用 K-Means（月牙或环形数据需要 DBSCAN）
- DBSCAN eps 设太大（全进一个簇）或太小（全是噪声）
- 把簇标签当真值（聚类是探索性的；用领域知识验证）
- 在超过 20,000 点的数据集上跑层次聚类（内存和时间爆炸）
